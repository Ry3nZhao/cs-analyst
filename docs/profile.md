## 命令

`get_profile({ steamid, options? })` → `ProfileDto`

- `options.window`：趋势滑动窗口（场），默认 10，范围 1–200。
- `options.lastMatches`：只统计最近 N 场；不传 = 全部。
- `steamid` 是主玩家；后端会通过 W1-C 的身份表找到同一个人名下的**全部** steam 身份一起统计（合并过的账号都算）。

页面：没设置主玩家时显示引导，`useMainPlayer().suggestion` 可以一键采用，或去 `/welcome`。新对局解析完成（`analysis_updated` = done）后自动刷新。

## 指标

每个指标在每场里是一个「分子 / 分母」对，跨场时**先把分子分母分别相加再相除**（不是把每场的比率再平均）。某场**不可用**的指标不参与相加，也不当成 0。

| key | 名称 | 分子 / 分母 | 方向 | 不可用的情况 |
|---|---|---|---|---|
| `adr` | ADR | 有效伤害 / 回合 | 高 | — |
| `kast` | KAST | KAST 回合 ×100 / 回合 | 高 | — |
| `kd` | K/D | 击杀 / 死亡（死亡为 0 时按 1） | 高 | — |
| `rating` | HLTV 2.0 | 单场 rating × 回合 / 回合 | 高 | — |
| `swing` | Swing | `swing_total` / 回合 | 高 | 迁移 006 之前、还没回填的行 |
| `openingDuel` | 首杀率 | 开局对枪成功 ×100 /（成功 + 失败） | 高 | 没参与开局对枪 |
| `clutch` | 残局胜率 | 1vN 获胜 ×100 / 1vN 次数 | 高 | 没打过残局 |
| `ttd` | TTD | 中位数 × 样本数 / 样本数 | 低 | 没有枪法数据，或可见性不可靠（ESL demo） |
| `crosshairPlacement` | 准星位置 | 同上 | 低 | 同上 |
| `counterStrafe` | 急停率 | 急停成功 ×100 / 首发数 | 高 | 没有枪法数据 |
| `sprayError` | 压枪误差 | 平均误差 × 连发数 / 连发数 | 低 | 没有连发 |

TTD 和准星位置跨场用「各场中位数按样本数加权平均」近似整体中位数。

- **总值**：统计范围内全部场次。
- **最近**：最近 `window` 场。
- **趋势**：每场一个点；滑动平均 = 当前场及之前共 `window` 场里有数据的那些场，按上面的规则合并。窗口里一场都没有数据时为 `null`（图上断开）。

## 段位与百分位

### 段位口径

段位来自 demo 里记录的平台分数（`match_players.rank` / `rank_type`，即 `CCSPlayerController.m_iCompetitiveRankType`）：

| rank_type | 体系 | 分桶 |
|---|---|---|
| 11 | Premier（CS Rating） | 按官方颜色：< 5000、5000–9999、10000–14999、15000–19999、20000–24999、25000–29999、30000+ |
| 12 | 竞技段位（1–18） | 白银 1–6、黄金新星 7–10、AK–菊花 11–14、老鹰及以上 15–18 |
| 7 | 搭档段位（1–18） | 同上，单独一个体系 |

- 分数为 0（未定级）或其他 `rank_type` 的行不参与分段。
- 主玩家的段位 = **最近一场有分数的对局**里的分数所在的桶。
- 同段位样本 = 其他选手在**那一场的分数**落在同一体系、同一个桶里的那些「选手 × 对局」行。也就是说一个人在不同段位时打的比赛，会分别进入不同的桶。
- 平台 demo（5E 等）里 `rank` 一般是 0，平台自己的 ELO 目前没有入库（下载模块没取），所以平台对局不参与分段，头部也不显示 5E ELO。以后入库了，在 `compute::ScoreSystem` 里加一个体系即可。

### 百分位口径

- **样本单位**：其他选手（按 steamid，排除主玩家名下所有 steamid），把他在样本行里的数据按上面的规则合并成一个值。
- **样本门槛**（每个指标单独判断，太少的人不进样本）：ADR / KAST / K/D / HLTV / Swing 至少 10 回合；首杀率至少 3 次开局对枪；残局至少 2 次；TTD / 准星至少 5 个样本；急停至少 10 次首发；压枪至少 3 次连发。
- **降级**（每个指标单独判断）：
  1. 同段位样本 ≥ 15 人 → 用同段位（`scope = tier`）。
  2. 否则全库样本 ≥ 8 人 → 用全库（`scope = all`），界面注明「同段位只有 x 人，改用全库 y 人」。
  3. 否则不给百分位（`scope = none`），界面显示「样本不足（n 人）」。
- **计算**：百分位 = 样本里比自己差的人数占比，相等算一半，已按指标方向处理（TTD、准星、压枪误差越低越好）。P50 = 样本中位数。
- **低置信**：样本 < 30 人，或主玩家自己的数据没达到上面的门槛，界面在百分位旁标「参考」。
- 界面在「关键指标」标题下写明段位、使用的样本和人数。

### 重点改进

有百分位、且低于 P50 的指标，按百分位从低到高取至多 3 项。每项显示自己的值、样本中位数，链接到 `/highlights?type=mistake&days=30`（W3-A 的失误集锦）。没有符合条件的指标时说明原因（样本不足 / 都在中位数以上）。

## 分项与个人最佳

- **地图**：按 `matches.map_name` 分组，指标规则同上。
- **T / CT**：按 `player_round_stats` 的回合阵营统计（只算参加了的回合）：回合胜率、K/D、ADR、KAST、开局对枪、Swing。
- **武器**：击杀来自 `kills` 表（只算击杀敌人，丢弃最后一回合结束后的事件，和计分板一致）；武器名用 `aim::weapons::canonical` 归一（平台皮肤名），刀统一为 `knife`，燃烧瓶 / 燃烧弹为 `inferno`。开枪、命中、爆头命中来自 `player_match_aim`。
- **个人最佳**：单场击杀、ADR、HLTV 2.0、Swing、爆头击杀、单回合最多击杀（nK）、最大残局胜利（1vN）、单场最快 TTD。并列时取最近的一场。每项链接到 `/matches/[id]`。

## 校验

`cargo test --lib profile -- --nocapture`：用主玩家（`CS_ANALYST_SAMPLE_STEAMID`）的 3 场样例 demo（官匹 Premier 3392、两场平台 demo）入库后检查：

- 汇总 3 场 2 胜 1 负，36 杀 25 死，45 回合；ADR 85.82、KAST 71.1%、K/D 1.44、HLTV 1.273、Swing +0.49、首杀率 40%、残局 0/3、TTD 208 ms、准星 2.03°、急停率 50.8%、压枪误差 3.19°。
- 其中一场平台 demo 可见性 0.63（不可靠）：TTD / 准星只来自另外两场，`matchesWithData = 2`，该场趋势点为 `null`。
- 段位 Premier 3392（< 5000 桶），同段位只有 4 人 → 全部指标退回全库（27 人，TTD / 准星 18 人），都标低置信；ADR P59、K/D P70、TTD P72、准星 P94、急停率 P33。
- 重点改进依次为急停率、残局、首杀率。
- 把全库选手都改成同一个 Premier 桶后，改用同段位样本，百分位不变。
- 窗口 2 时最后一个滑动点 = 最近两场合并；`lastMatches = 1` 只剩最新一场；未知 steamid 返回空主页。
