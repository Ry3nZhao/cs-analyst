# 路线图

[← 文档目录](README.md) · [项目介绍](../README.md)

> 状态：规划稿 v2（2026-11）
> 目标：在已有的「多平台 demo 自动发现 + 下载」之上，补齐 **解析 → 指标 → 展示 → 训练** 全链路。分析深度对标 Leetify，同时支持 5E、Renown 等国内平台，并能看全库对手的对位数据。

---

## 0. 基本原则

| 原则 | 含义 |
|---|---|
| **纯本地** | 不注册账号、不上传、无云端、无遥测。联网只用于用户自己配置的平台下载。所有数据都放在本地数据目录，可整体拷走 |
| **技术栈统一** | Rust（Tauri）+ Vue / Nuxt。解析和分析全部在 Rust 里完成，不引入 Go 或 Python |
| **先做 Windows** | 开发、测试、发版目前只覆盖 Windows；macOS / Linux 之后再说 |
| **评分从简** | 不做 Leetify Rating 这类综合分，只做 **Swing**（回合胜率摆动）。其余指标展示原始值，再加上在本地样本里的百分位 |
| **基准用本地样本** | 同段位对比只用本地库里的数据，不附带外部基准表 |

## 1. 现状

| 环节 | 现状 | 缺口 |
|---|---|---|
| 账号 | 用户 / 子账号，接入了 5E、Renown、Valve Auth Code | 只覆盖「我自己」，没有「任意玩家」的身份体系 |

## 2. 功能清单

数据来源标记：**E** = 事件级（击杀、伤害、道具、回合）；**T** = tick 级（每个 tick 的视角、位置、速度、后坐力、可见性）。

### 2.1 基础数据（E）

K/D、ADR、KAST、HS%、HLTV 2.0（作为参照）、多杀、MVP、存活率、每回合道具伤害。

### 2.2 Swing（回合胜率摆动）

- 用本地全部回合拟合一个胜率模型：T 方胜率 = f(双方存活人数、装备价值差、是否已下包、剩余时间)。样本少时先用分段查表加平滑
- 每个事件（击杀、伤害、下包、拆包、闪光助攻）发生前后各算一次胜率，差值按贡献归因到个人：击杀者拿大头，造成伤害的人、闪光助攻者按比例分；死亡者扣分，如果被队友补回则少扣
- 展示：每人每回合的 Swing、整场平均 Swing、比赛详情页里每回合的胜率曲线

### 2.3 枪法（T 为主）

| 指标 | 定义 |
|---|---|
| Time to Damage | 敌人进入视野到第一次造成伤害的时间（ms） |
| 准星位置 | 敌人进入视野那一刻，准星和敌人头部的夹角（°），分垂直和水平两个分量 |
| 反应时间 | 敌人进入视野到第一次开枪的时间 |
| 急停率 | 开枪时速度低于该武器精准阈值的比例 |
| 命中率 / 可见时命中率 | 全部开枪的命中率，以及只算敌人可见时开枪的命中率 |
| 首发命中率、爆头命中率 | E |

### 2.4 压枪弹道分析（T）

- **连发识别**：同一把自动武器，相邻两枪间隔不超过射速间隔 × 1.5，算作一次连发
- **每发子弹记录**：开枪时的视角（pitch / yaw）和后坐力偏移（`AimPunchServices.m_predictableBaseAngle`）。实际弹道方向 = 视角 + 后坐力 × 2（CS 的后坐力缩放系数）
- **补偿误差**：以第一发为原点，每一发的实际方向和第一发的偏差，就是这一发没压住的量。分垂直方向（压多了还是压少了）和水平方向（左右摆）
- **有目标时**：再算每一发和敌人头部、身体的偏差
- **展示**：
  - 单次连发的弹道图：玩家实际轨迹叠在理想点上，逐发编号
  - 按武器（AK / M4A4 / M4A1-S / …）汇总：平均弹道、第 N 发的平均误差曲线、「第几发开始崩」
  - 趋势：每把武器压枪分数的时间曲线
- 先做 AK-47、M4A4、M4A1-S、Galil、FAMAS、MP9、MAC-10，之后再扩展到其他武器

### 2.5 道具（E）

每颗闪光平均致盲敌人数和致盲时长、闪光助攻、闪到队友、每颗 HE 的平均伤害、HE 误伤、燃烧弹伤害、每回合投掷数、死亡时没用掉的道具价值。

### 2.6 对枪、补枪、残局（E）

开局对枪（尝试率、成功率，分 T / CT）、补枪机会和成功率、被补率、残局 1v1 到 1v5、首死位置分布。

### 2.7 身份与对位（全库）

**身份模型**：一个「人」（person）下面绑定多个「身份」（identity）。身份包括 Steam64、5E UID、Renown ID、完美 ID 等。绑在一起的就是同一个人。

- **自动关联**：
  - demo 里的 steamid 是跨平台的公共键，同一个 steamid 自动归为同一个人
  - 平台账号（5E / Renown）通过平台接口或 demo 里的数据关联到 steamid
- **手动操作**：合并（小号、换号）、拆分（错误合并）、备注、标签
- 现有的「用户 / 子账号」变成特例：标记为「我关注的人」的 person
- **对位数据**：库里只要有和某人同场的比赛，就能看到：
  - **交手战绩**：同队 / 对面各多少场，各自胜率
  - **直接对枪**：互杀数、互相造成的伤害、对枪胜率（每回合两人第一次交火的结果）、开局对枪战绩
  - **同位置对位**：双方都用 AWP、或者同一个包点的进攻和防守，在同一区域内的表现对比
- **对手查询**：搜任意玩家，看他在本地库里的全部数据和常用武器、常站位置
- **组排**：常一起排的队友，组排时的胜率和数据变化

### 2.8 比赛详情页

- 计分板：多个标签页，分别是基础、枪法、道具、对枪、经济、Swing
- 回合时间线：胜负原因、经济类型（全起 / 强起 / ECO）、击杀流水、每回合胜率曲线
- 伤害矩阵、对枪矩阵、经济曲线
- 2D 回放（位置数据默认解析）、热力图、道具落点
- 点任意一个玩家，直接跳到他的对位数据

### 2.9 高光 / 失误集锦

**自动识别规则**（每条都带权重，可在设置里开关）：

| 高光 | 失误 |
|---|---|
| 3K / 4K / ACE、短时间内连杀 | 首死且没被补 |
| 残局胜利（1vN） | 死亡时道具一颗没用 |
| 大角度甩枪爆头（击杀前几个 tick 视角变化大） | 闪到队友、队友伤害 |
| 穿墙、盲杀、穿烟、跳杀、无镜狙 | 有血量优势却输掉 1v1 |
| 本回合 Swing 很高的关键击杀 | 近距离连发全空 |
| 关键拆包、忍者拆包 | 换弹时被杀 |
|  | 单次事件导致的大幅负 Swing |

**浏览与播放**：
- 每场比赛有集锦列表；也能跨比赛汇总，例如「我最近 30 天的所有失误」，并按类型筛选
- **在 CS2 中播放**：用 `playdemo` 打开 demo，跳到事件前几秒的 tick。可以用 CS2 的 `-netconport` 本地控制台端口发送 `demo_gototick`（需要验证是否可行）；不行就退回到「复制命令 + 打开 demo」
- **导出视频**（后期）：HLAE + FFmpeg 本地录制，把一组片段拼成集锦视频

### 2.10 个人主页

各项指标的趋势（最近 N 场滑动平均）、地图 / 武器 / T 侧 / CT 侧统计、个人最佳、平台分数历史（Premier、5E ELO 等）。

每项指标都显示在本地同段位样本里的百分位，并自动挑出最差的 2–3 项，作为「重点改进」，附带对应的失误集锦。

### 2.11 瞄准训练（内置）

自己设计的训练小游戏，在应用里开个窗口就能练。用 Canvas / WebGL 渲染，开 Pointer Lock 读原始鼠标输入。

| 模式 | 内容 | 记录 |
|---|---|---|
| 反应测试 | 屏幕变色后尽快点击 | 平均值、中位数、最好成绩 |
| 甩枪 | 随机位置出现小目标，限时点击 | 命中率、单个目标用时 |
| 跟枪 | 跟住移动目标 | 在目标上的时间占比 |
| 微调 | 目标出现在准星附近的小范围内 | 精度 |
| 急停节奏 | 按住 AD 移动，在速度归零的窗口内开枪 | 急停成功率 |
| 压枪练习 | 按选定武器的弹道把准星往回拉 | 和 2.4 共用误差算法 |

- **灵敏度对齐 CS2**：读取 CS2 配置里的 `sensitivity`，也可以手动输入，保证手感和游戏里一致
- **训练记录**：成绩存在本地，有趋势曲线
- **联动**：训练成绩可以和比赛里的 TTD、急停率、压枪误差放在一起看
- **提示**：WebView 有一定输入延迟，反应测试的数值只适合和自己以前的成绩比，不能和其他工具横向比

## 3. 技术方案

### 3.1 整体结构（重构后）

```
Nuxt 4 UI（Vue）
     │ Tauri IPC
     ▼
Rust（Tauri）
 ├─ crates/demo-parse   基于 demoparser2 fork：事件 + tick 字段
 ├─ crates/analysis     指标计算、Swing、集锦识别、压枪分析
 ├─ crates/identity     person / identity 关联与合并
 ├─ downloader（独立模块，将来做成 submodule）  5E / Renown / Valve 发现与下载，JSON-RPC
 └─ src-tauri           调度、队列、数据库、IPC
```

- **解析器**：fork demoparser2（Rust，MIT），以 vendor 方式引入（已验证可用，见第 6 节），按需读取 tick 字段（坐标、pitch / yaw、速度、AimPunchServices、spotted、武器状态）
- **自研和 fork 的分界**：底层 demo 协议解析（sendtables、实体）直接沿用；指标和派生数据全部自己写

### 3.2 下载模块化（Node sidecar 的去向）

下载功能本身只需要「能被主程序管理地下载」，不追求用什么语言实现。所以把它定义成一个**独立的下载模块**，而不是强行重写成 Rust：

- **接口固定**：主程序通过 JSON-RPC（stdio）调用 `discover` / `download` / `cancel` / `health`，并接收进度事件。现有 `rpc.ts` 的协议就是这个接口，先把它写成文档、加上版本号
- **主程序负责管理**：启动、停止、崩溃重启、超时控制、并发、重试、日志收集、版本检查，都由 Rust 编排层负责。模块只管「给我账号，返回比赛和文件」
- **按平台独立**：每个平台是模块里的一个 adapter，可以单独启用或停用，单个 adapter 出错不影响其他平台
- **将来做成 git submodule**：先把 `src/sidecar` 的边界整理干净（不依赖主仓库的其他代码，`shared-types` 里的协议类型单独打包），之后再拆成独立仓库，用 submodule 引入
- **Rust 侧只做协议解析**：文件头解析 `dem-parser.ts` 会被 `demo-parse` 取代，之后下载模块不再碰解析

### 3.3 存储

| 数据 | 放在哪 | 原因 |
|---|---|---|
| 比赛、回合、击杀、伤害、开枪（含视角）、道具、经济、残局、集锦、身份、派生指标 | SQLite | 需要跨比赛查询（对位、趋势、基准） |
| 逐 tick 位置和视角（2D 回放、热力图） | 每场一个列式压缩文件 `analysis/{match_id}.bin`（zstd） | 一场有上百万行，放进 SQLite 太大；也只在打开单场时才用到 |

- 位置数据**默认解析**。2D 回放按每 4 tick 采样一次存储；TTD 和准星位置这类计算在解析时用全精度做完，结果写入 SQLite
- `analyzer_version`：指标算法升级后可以一键重算。只要原始事件和 tick 文件还在，就不需要重新解析 demo

### 3.4 新增表

```
schema_migrations
analysis_jobs
persons / identities / person_merges       身份体系
match_players                              match × identity，含当场段位
rounds / kills / damages / shots / grenades / blinds / bombs / clutches / economies
sprays / spray_shots                       压枪
highlights                                 集锦（类型、tick 区间、分数、涉及玩家）
player_match_stats / player_round_stats    派生指标（含 Swing）
h2h_stats                                  person × person 对位汇总（物化表，解析后增量更新）
training_sessions / training_results       瞄准训练
```

## 6. 验证结果（2026-11-05）

用 demoparser2（上游 main 分支）写了一个探针程序，跑了本地 `<sample-dir>` 下三个来源的 demo：Official（Valve 官匹）、Platforms（`g161-n-*`）、Profs（2026 Major，ESL 服务器）。

### 6.1 解析能力：✅ 满足 P2 / P4 / P6 的需要

| 项目 | 结果 |
|---|---|

**fork 时要做的改动**：
- `csgoproto` 和 `parser` 的 `build.rs` 会在构建时 `git clone` GameTracking-CS2 并调用 `protoc`。生成好的代码其实已经提交在仓库里，fork 后把这两个 `build.rs` 改成空实现，就能离线构建
- 修正后坐力相关的友好名映射
- 上游仓库很大（带测试 demo），用 vendor 方式引入，只保留 `src/parser` 和 `src/csgoproto`

### 6.2 steamid：✅ 三个来源都完整

三个来源的 10 名玩家都有合法的 Steam64，击杀事件里也带 `attacker_steamid`。

实际例子：76561198000000042 在官匹里叫 `PlayerAlt`，在平台 demo 里叫 `PlayerOne`，按 steamid 会自动归为同一个人。P3 的自动关联可以成立；平台账号（5E UID 等）和 steamid 的对应关系由各平台 adapter 提供。

### 6.3 CS2 `-netconport`：⚠️ 需要在本机实测

- Windows 上有已知问题（[ValveSoftware/csgo-osx-linux#3603](https://github.com/ValveSoftware/csgo-osx-linux/issues/3603)，至今未关闭）：端口在 WSAStartup 之前就初始化了，只能加 `-tools` 绕过
- 也有人报告 `-insecure -netconport 2121` 在 Windows 上可用（[diamond-cs2-v2#14](https://github.com/cooperwooley/diamond-cs2-v2/issues/14)），但部分命令需要先开 `sv_cheats 1`
- 结论：P7 先做「`+playdemo` 启动 + 复制跳转命令」作为保底方案；本机实测 netconport 能用后，再加自动跳转

### 6.4 Steam GC 下载：不再作为阻塞项

下载保持为独立管理的模块（3.2 节），能下载就行，不要求改用 Rust 实现。
