# 基础指标口径

[← 文档目录](README.md) · [架构](architecture.md) · [路线图](roadmap.md)

基础指标由 `crates/stats` 计算，这是一个纯函数 crate，输入一场比赛的事件，输出 `MatchStats`。`src/stats/` 负责入库和 Tauri 命令。

## 数据流

```
解析 worker：replace_match_analysis（002 事件表）
        └─ stats::on_match_ingested → stats::compute(&ParsedDemo) → 003 三张表
启动：stats::spawn_backfill → 已解析但没有统计、或 stats_version 过旧的对局 → 从 002 表读回事件 → 重算
get_match_detail：从 002 表读事件 → 实时计算（单场只要几毫秒）→ 若库里版本不对，顺便回写
list_player_stats：只读 player_match_stats
```

修改任何指标定义时，都要提升 `stats::STATS_VERSION`。启动时会用已入库的事件自动重算，不需要重新解析 demo。

## 约定

- **阵营**：2 = T，3 = CT。玩家每回合的阵营取 freeze end 时的经济快照。没有快照的回合视为没参加（例如掉线），不计入 `rounds_played`。
- **队伍**：与阵营无关。A = 第一回合打 CT 的一方，B = 第一回合打 T 的一方。每回合按 A 队多数成员的阵营判断换边，半场和加时都适用。比分、胜负都按队伍统计。
- **击杀**：只算击杀敌人。自杀（attacker = victim，或没有 attacker，比如摔死、C4 炸死）和队友击杀都不算，分别计入 `suicides` 和 `team_kills`。
- **死亡**：每条死亡事件都算，包括自杀，和游戏内计分板一致。
- **比赛结束后的事件**：最后一回合 `end_tick` 之后的事件全部丢弃，例如平台服务器在比赛结束时产生的 `world` 自杀。其他回合结束后的补枪仍然算在该回合。
- **伤害**：只算对敌人造成的有效伤害，即不超过对方剩余血量。队友伤害不计入 ADR。
- **致盲**：如果 demo 里有闪光弹但没有 `player_blind` 事件（ESL 服务器），所有致盲类字段都是 `NULL` / `null`，不是 0；`blindDataAvailable = false`。闪光助攻来自击杀事件，不受影响。

## 指标

| 指标 | 定义 |
|---|---|
| K / D / A | 见上。A 包括闪光助攻；助攻者必须是击杀者的队友 |
| ADR | 有效伤害 / 参与回合数 |
| KAST | 有击杀、助攻、存活、或死亡被补枪的回合占比 |
| HS% | 爆头击杀 / 击杀 |
| HLTV 2.0 | `0.0073·KAST + 0.3591·KPR − 0.5329·DPR + 0.2372·Impact + 0.0032·ADR + 0.1587`，其中 `Impact = 2.13·KPR + 0.42·APR − 0.41`。这是社区反推的公式，仅作参照 |
| 多杀 | 单回合击杀数 2–5 的回合数（`multiKills[n]`） |
| MVP | 近似值。CS2 的 `round_mvp` 事件没有解析，规则是：炸弹爆炸算下包者，拆包成功算拆包者，否则算获胜方击杀最多的人（再比伤害） |
| 存活率 | 回合结束时仍存活的回合占比 |
| 开局对枪 | 每回合第一个敌对击杀（回合结束前）。击杀者算成功，被杀者算失败，按当时的阵营分 T / CT |
| 补枪窗口 | 5 秒 |
| 补枪机会 / 尝试 / 成功 | 队友阵亡时自己还活着 = 一次机会；5 秒内对凶手造成伤害 = 尝试；5 秒内击杀凶手 = 成功（`tradeKills`） |
| 被补 | 阵亡时还有队友存活 = 一次机会；凶手 5 秒内被队友击杀 = 被补（`tradedDeaths`）。被补的死亡同样计入 KAST |
| 残局 1vN | 一方第一次只剩 1 人、另一方还有 N ≥ 1 人时，记为这名玩家的一次 1vN（N 最大计 5）。每回合最多一次。所在方赢下这回合就算残局获胜；残局开始后的击杀计入 `clutchKills` |
| 闪光 | 每颗闪光致盲敌人数 / 致盲时长 = 致盲敌人次数（或时长）/ 闪光数。只统计当时还活着的目标，自闪不算；闪到队友另外计数 |
| HE / 燃烧伤害 | 武器 `hegrenade`、`inferno` / `molotov` 对敌人造成的有效伤害；HE 误伤 = HE 对队友造成的伤害 |
| 每回合投掷数 | 五类道具的爆炸 / 起火事件数 / 回合数 |
| 死亡时未用道具价值 | 近似值。用「购买 − 投掷」推算身上的道具，存活则带到下一回合，换边时清空；死亡时剩下的道具按价格计。捡起和丢弃道具无法从事件看出来 |
| 经济类型 | 半场第一回合（第 1 回合和第一次换边后的那一回合）是手枪局。其余回合按全队平均装备价值分：低于 $2000 是 ECO；T 方达到 $3500、CT 方达到 $4000 是全起；中间是强起。装备价值 = freeze end 时的装备价值 + 之后的购买 |
| 比分走势 | 每回合结束后两队的比分（`team_round_stats.score`，以及回合时间线里的 `scoreA` / `scoreB`） |

### 购买事件的坑

`item_purchase` 会在玩家死亡或回合末尾**再成批重发一次**，同一个 tick 会出现多件物品。所以只统计 freeze end 之后 21 秒以内的购买，也就是购买时间加上少量余量。

## 表结构（迁移 003）

- `player_match_stats`：主键 `(match_id, steamid)`，存上面全部计数，另存一份 `adr` / `kast` / `hs_pct` / `rating` 方便排序。`won` 取 1、0，或 `NULL`（平局）。`stats_version` 记录算法版本
- `player_round_stats`：主键 `(match_id, round, steamid)`。存每人每回合的击杀、死亡 tick、伤害、KAST、补枪、开局对枪、残局、MVP、装备、余额、道具。第二波的 Swing 可以在后续迁移里往这张表加列
- `team_round_stats`：主键 `(match_id, round, team)`。存阵营、胜负、赛后比分、装备、余额、经济类型、击杀数、存活人数

三张表都随 `matches` 级联删除。

## 校验

`cargo test -p stats --release -- --nocapture` 用 3 个样例 demo，逐人和 demo 里保存的**游戏内计分板**做对照。计分板数据来自 `CCSPlayerController_ActionTrackingServices`，在最后一个 tick 读取：

- 官匹、职业：K、HS 全部一致；A 的误差不超过 1；伤害的误差不超过 2%（实际大多在 1% 以内，原因还没查清）
- D：只有「比赛结束后的 `world` 自杀」这一项和游戏不同，游戏会算，我们不算
- 平台 demo（`g161`）：2 名玩家的 K 和游戏差 1，伤害差 6–8%，原因还没查清。计分板的伤害本身会滞后一回合更新，所以必须在最后一个 tick 读取
